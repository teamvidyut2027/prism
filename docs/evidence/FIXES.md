# Development fix log

The guideline asks for "documented manual fixes". Prism never hand-edits generated tasks: every fix below was a change to the **pipeline**, followed by regenerating the data. Each entry says how the problem was detected; most were caught by the pipeline's own validation layers.

| # | Problem | How it was detected | Fix | Effect |
|---|---|---|---|---|
| 1 | Line-chart points were sometimes unreadable to the verifier: thin, nearly flat 2.6 px strokes are anti-aliased across two rows, so no pixel was close to the pure series colour. | Verifier self-check: 178/200 line charts agreed. | Replaced the fixed colour threshold with an **alpha-blend coverage model** (`palette.coverage`) and two-sided segment extrapolation at each tick. | 297/300 agree; the rest are points genuinely hidden where series cross, which the factory now rejects. |
| 2 | Object scenes reported a phantom small "gray star". | Verifier self-check: 195/200; the object count was off by one. | The anti-aliased rim of brown objects also fit the gray blend line. Added **exclusive coverage**: each pixel goes to the single palette colour that explains it best. | 200/200 agree. |
| 3 | Every maze failed verification with one extra wall. | Verifier self-check: 0/300. | The green start marker is darker than the luminance threshold. Walls are now classified with the same exclusive colour model. | 300/300 agree. |
| 4 | Table OCR rejected correct digits (scores ~0.65). | Verifier self-check: only level 1 passed. | Templates were rendered at a single sub-pixel phase. They are now rendered at 8 phases, and a glyph is accepted on a **margin over the runner-up** instead of a fixed score. | 200/200 agree. |
| 5 | Almost no table perturbation twins survived (8% under noise, 0% under blur). | Audit: perturbation recovery per family. | Blur merges neighbouring digits, so gap-based segmentation fails. Switched to **fixed-pitch segmentation** (right-aligned monospace digits at known advance positions) with blur-matched templates. | Noise 78%, JPEG 66%. Remaining drops are truly illegible 14 px digits under heavy blur, and they are excluded rather than mislabelled. |
| 6 | 69% of yes/no gold answers were "yes". | Dataset stats: `boolean_true_pct`. | Question selection now picks templates uniformly, then **flips a coin for the yes/no target** and picks parameters that hit it. Maze reachability is sampled 50/50. | 51.8% yes; the blind-prior ceiling fell from 42.7% to 24.7%. |
| 7 | Same-layout tables with different numbers were flagged as near-duplicates. | Funnel: 7 tables rejected as near-duplicates. | 64-bit dHash was too coarse. Now an exact **content hash** of the facts plus a 256-bit dHash with a tight threshold. | Only genuine duplicates are removed. |
| 8 | Only 74% of base tasks got a counterfactual twin (lines: 27/40 failed). | Funnel: "no answer-flipping edit found". | Mutations are now **targeted at the element the question refers to** (that bar, that series point, that object or cell), and every question of the task is tried, not one at random. | 233/237 (98%). |
| 9 | Awkward grammar, e.g. "How many museums have a visitors greater than 12?" | Gallery review in the dashboard. | Renamed chart measures ("visitor count", "sales volume", "points total", "power output") and printed every template × parameter combination for review. | All phrasings read naturally. |
| 10 | `question_meta` crashed for line-chart templates without `a`/`b`. | Factory run (KeyError). | The lookup no longer evaluates other templates' parameters. | Build passes. |
| 11 | Leaderboard showed "No evaluations yet" although runs existed. | Browser check of the dashboard. | `/api/runs` stripped full metrics; it now returns them. | Leaderboard and heatmap render. |
| 12 | Tests could pick up the real API key from `.env` and start a paid run. | Code review after adding `.env` loading to the server. | `PRISM_NO_DOTENV=1` in the test suite; the key is also removed from the environment. | Tests are offline by construction. |
| 13 | The Linux Docker build produced different pixels for every image with text (bars, lines, tables, maze labels), while shapes and clocks matched exactly. Questions were identical. | `prism reproduce` in Docker: fingerprint FAIL. A per-task digest diff isolated the families with text. | Pillow on Windows shapes text with Raqm/HarfBuzz (kerning); the slim Linux image lacked `libfribidi`, so Pillow fell back to basic layout. Added `libfribidi0` to the image, made the layout engine explicit, and `reproduce` now reports the engine and explains a mismatch. | Linux container and Windows builds are **byte-identical** (fingerprint `ce14c7fc...`, `logs/reproduce_docker.log`). |

## Model-side checks (not pipeline fixes)
